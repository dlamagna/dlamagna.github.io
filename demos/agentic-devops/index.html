Agentic DevOps: managing a team of AI coding agents

A Claude Code plugin that lets one lead AI agent run a team of helper agents on the same codebase, while keeping their work easy to review, safe to merge and gentle on the computer it runs on.

Private repository: this page explains how it works.

How a piece of work moves

  1. Plan

    The lead agent splits the project into small tasks, each with a clear goal and the tests that prove it is done.

  2. Build

    A helper agent takes one task in its own copy of the code and writes the tests first. New helpers only start when the computer has room for them.

  3. Review

    A second agent tries to break the work before anyone sees it. Its findings go back to the helper that wrote it, which still remembers the task.

  4. Check

    Every automated check has to pass, on the computer and on GitHub. A failing check gets fixed, never switched off.

  5. Merge

    The lead combines the work with the latest version and merges it once everything is green. Nothing merges without an explicit go-ahead.

  6. Keep going

    The project board stays up to date at every step, and an overnight run that hits a usage limit restarts on its own.

What is in the plugin

15 tools for the lead

Starting and tracking helpers, sharing the computer's memory fairly, running the checks, merging, updating the project board, and writing notes for the next session.

Rules that cannot be skipped

A guard checks every command before it runs, and blocks the risky ones: merging without the checks, changing the main version directly, or starting more helpers than allowed.

Instructions for each role

Ready-made briefs for the lead, builder and reviewer agents, and starting prompts for planning, daytime work, handovers and overnight runs.

Safe by default

It uses the existing GitHub login and stores no passwords, never merges work the owner has reserved, and keeps a log with sensitive details removed.

Result

Used to build Margin: 81 changes merged, up to about 20 in progress at once, with one person reviewing. The review step caught serious bugs in about half of the changes, including security holes, that the helpers' own tests had missed.
